# ADR-0001：端侧优先，不上云

- 状态：已接受
- 日期：2026-10-20

## 背景
用户要复刻夸克扫描王的扫描和 AI 矫正，要求「识别准确、速度快」，并明确要求 **尽可能避免云上处理，优先本地快速处理**。

调研（`docs/research/`）发现：
- 夸克默认的「智能」滤镜和多数重度 AI 处理走云端（上传压缩图 → 服务端处理 → 下载），没网时受限；用户吐槽「涂抹感」、字形被改、必须联网。
- 夸克自己的离线流水线只用了 1–2 MB 级的小模型：找文档 → 四点/六点回归 → TPS 展平 → 边缘吸附 → 经典增强，官方称效果约为云端的 95%。
- iPhone 上系统自带的 Vision（文档分割、OCR）、Core Image（透视校正）、PDFKit 已覆盖大部分需求，且跑在神经引擎/GPU 上。

## 决定
1. **所有处理都在设备上完成**：找边、几何矫正、展平、增强、OCR、PDF 生成。App 不包含任何上传图片或调用推理服务的代码。
2. **不引入需要联网下载资源的依赖**（例如运行时下载语言包的 OCR）。模型随包或作为 App 内资源，不做远程下发。
3. **级联小模型**：预览用系统 Vision；拍后平纸只做 `CIPerspectiveCorrection`；书页用自训 ≤2 MB 的 4/6 点回归网络 + TPS；只有残余弯曲严重时才调用 UVDoc（MIT，Core ML FP16）。随包模型合计 ≤ 25 MB。
4. **工作图与原图分离**：算法在长边 1600–2048 px 的副本上运算，参数映射回原图做最终重采样；原图始终保留。
5. **保真模式**只做几何；增强默认用确定性经典算法；AI 增强是一个只在本地运行的显式开关。
6. 存储只在本机（以及用户自己选择的「文件」/iCloud 目录）；我们不运营服务器。

## 后果
- 好处：离线可用、隐私好、延迟稳定、没有服务器成本，并直接针对竞品的痛点。
- 代价：无法用云端大模型做去手写、去水印、超分之类重度处理（这些本来不在需求范围）；模型必须小，需要自己合成数据训练 4/6 点回归网络；低端机（A14）需要降级策略。
- 任何想引入网络请求的改动都必须先新增 ADR 并经用户同意。
