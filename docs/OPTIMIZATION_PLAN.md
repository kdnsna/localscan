# LocalScan 优化审计与实施计划

> 审计基线：iOS 17 / SwiftUI，所有处理在端上完成。以下耗时、内存和识别质量目标都必须用真机与真实测试集复核；静态检查不能替代这些指标。网页原型只作交互和经典算法对照，不复用其联网 OCR 路径。

## 优先级原则

1. 先避免误覆盖、误删除、内存崩溃和文字损坏，再增加功能。
2. 保真模式只做几何；增强和黑白必须确定性处理，不生成或修补文字。
3. 平纸不运行 UVDoc；模型、Metal 或推理失败时安全保留透视结果。
4. 不引入第三方运行时依赖，不增加网络能力。

## P0：本轮最高优先级

### UI / 扫描流程

- **相机状态不可见**：授权正常时的拍摄失败、会话中断没有界面反馈；快门连点被静默拒绝。见 `LocalScan/Camera/CameraView.swift`、`CameraController.swift`。
  - 本轮：显示中断/错误状态；发布拍摄忙碌状态，禁用快门并给出进度及无障碍提示。
- **重拍容易误覆盖，删除不可恢复**：进入重拍后没有模式提示或取消入口，删除立即生效。见 `LocalScan/Flow/PageDetailView.swift`、`LocalScan/App/ContentView.swift`。
  - 本轮：重拍横幅与取消；删除确认。
- **导出状态误导**：处理失败也提示“正在处理”，分享前没有页数摘要。见 `LocalScan/Export/ExportSheet.swift`。
  - 本轮：显示“导出 N 页”，区分等待与失败，并预先禁用不可导出状态。

### 能力 / 稳定性

- **UVDoc 只有 stub**：没有模型和推理，弯曲页实际上仍为透视结果。
  - 本轮：加入 15.86 MB 的 MIT `UVDocCoreML.mlpackage`，保留 `UVDocDewarper(bundle:featureFlagEnabled:)` 和非抛出 `Dewarping` 接口；Core ML 输出 45×31 网格，Metal 全分辨率重采样，所有失败返回 nil。
- **连拍没有背压**：每次 `ingest` 都并发解码，多张全分辨率图会在串行处理队列之前驻留。
  - 本轮：把解码、找边和后续处理串成同一条有界任务链，保持拍摄入口不阻塞。
- **PDF 导出多次整体物化**：滤镜结果、`UIImage` 数组和最终 PDF `Data` 同时占用内存。
  - 本轮：逐页渲染滤镜并逐页写入 PDF，旧数组 API 保留为兼容包装。
- **极端透视可能生成超大位图**：输出 extent 没有像素预算。
  - 本轮：渲染前检查有限尺寸、最长边及总像素，超限失败并保留可重拍/重裁剪路径。

## P1：本轮质量与无障碍改进

### UI / 编辑与页面管理

- **拖放不是可访问的排序方式**：缩略图没有页码和状态朗读，也没有等价的前移/后移操作。
  - 本轮：缩略图补充“第 N 页，共 M 页”及状态；详情增加前移/后移按钮，复用 `ScanDocument.move`。
- **裁剪角点命中区只有 28 pt，VoiceOver 无法调整**。
  - 本轮：保持视觉尺寸，扩大至至少 44 pt；四角增加名称、坐标值和 `accessibilityAdjustableAction`，继续复用凸性/面积校验。
- **大字体下固定单行工具栏容易截断**：详情操作与裁剪底栏尤其明显。
  - 本轮：用 iOS 17 已有的 `ViewThatFits` 提供纵向回退；不照搬 Web 原型强制深色主题，原生继续跟随系统并使用系统材质/语义色。
- **详情滤镜在 `body` 中同步处理全图**：任何状态更新都可能重复运行 Core Image。
  - 后续：显示分辨率异步预览与按页面版本缓存；导出仍走全分辨率，避免本轮引入缓存失效风险。

### 能力 / 图像质量

- **预览和拍后找边校验不一致**：预览未统一拒绝非有限、凹形和过小框，可能污染平滑与自动拍摄。
  - 本轮：共用四边形有效性校验；自动拍摄原有更严格面积/稳定阈值不变。
- **黑白是固定 0.5 阈值**：阴影区域容易整体变黑或丢字，与项目计划的自适应阈值不符。
  - 本轮：复用低分辨率光照估计，在光照归一化后的灰度图上做阈值；增加阴影照明、纯黑白输出和确定性测试。保留原图像素不变。
- **找边失败与内缩框没有语义区别**：用户不知道需要确认裁剪。
  - 后续：让检测结果携带 `detected/fallback` 来源，拍后进入明确的手动确认流程；不能仅把内缩框当成功结果。

## P2：后续计划

- **透视与找边**：用复杂背景、小票、斜拍 30°/45° 的真实照片调阈值；评测细化后的最终框，而不是仅评 Vision 原始框。
- **详情与导出体验**：异步滤镜预览、导出进度/取消、统一 A4/Letter 选项；黑白页评估无损或更适合文字的压缩。
- **速度/内存**：详情预览降采样；长期页面位图缓存设上限；用 Instruments 测 20 页连拍和导出，目标峰值不超过 400 MB。
- **Vision OCR**：先实现独立的后台 `VNRecognizeTextRequest`（中英文、`.accurate`、本地已有语言支持），再把归一化观察框映射为 PDF 透明文字层。OCR 可选、失败不阻塞图像导出；用 PDFKit 验证检索并报告中英文 CER。
- **深色模式**：检查相机叠加层对比度、材料背景、失败/成功颜色不能只靠颜色区分；不采用 Web 原型的固定深色强制设置。
- **Web 原型差异**：相册导入、旋转、OCR 尚未在原生实现；原型裁剪允许非凸四边形，不能直接移植其确认逻辑。

## 本轮实施顺序与验证

1. UVDoc 资源、许可记录、兼容初始化与安全回退；检查模型名、输入输出名、FP16 strides、Metal 参数布局。
2. 串行采集处理、PDF 逐页写入、透视输出预算及对应单元测试。
3. 找边统一校验和光照归一化黑白及合成图回归测试。
4. 相机/重拍/删除/导出状态，页面排序与裁剪无障碍、大字体回退。
5. 全部 diff 做静态编译风险检查；无 Swift/Xcode 环境时明确标为未编译，不用 Python 测试替代 iOS 构建结论。

## 已完成 / 未验证 / 需真机

### 已完成

- UI 六项：相机错误/中断与快门忙碌反馈；重拍横幅和取消；删除确认；导出页数及失败/等待状态；页面状态朗读与前移/后移；裁剪 44 pt 命中区、VoiceOver 调整及大字体纵向回退。
- 能力六项：UVDoc FP16 + Core ML + Metal 集成及 nil 回退；采集解码串行背压；PDF 逐页渲染写入；透视 20 MP / 8192 px 输出预算；预览与拍后找边统一几何校验；黑白先归一化光照再阈值。
- 模型、MIT 许可、来源和 SHA-256 已入库；`.gitignore` 只精确放行该模型；`project.yml` 已加入 Core ML 构建源。
- 新增/更新单测覆盖 UVDoc 关闭回退、连拍顺序、可访问排序、逐页 PDF、透视预算、阴影黑白和确定性。
- 静态复核已修复 UVDoc 可选返回与位图所有权、面积阈值、模型被忽略等问题；`git diff --check` 通过。
- 已通过：无网络静态检查、5 个 Shell 检查样例、11 个 Python 评测测试；复制模型与参考目录一致，规格检查确认 488×712 RGB 输入和 `[1,2,45,31]` FLOAT16 输出。

### 未验证

- 当前机器没有 `swift`、`xcodebuild`、`xcodegen`，因此未生成 Xcode 工程、未编译 Swift、未运行任何 XCTest；新增测试目前只是静态审查通过，不能视为测试通过。
- 未在 Core ML runtime 加载模型或执行 Metal kernel；模型数值、图像方向、输出像素、资源编译为 `.mlmodelc` 均需 macOS/iOS 验证。
- 阴影黑白、PDF 页数/尺寸、透视预算和连拍顺序的新 XCTest 尚未实际运行；Python 检查不覆盖这些 Swift 行为。
- 未测量实际内存下降、PDF 导出速度或 UVDoc 全分辨率峰值内存；旧数组 PDF API 仅为兼容保留，App 导出入口已走逐页路径。
- Vision OCR、异步滤镜缓存、检测失败来源标记不在本轮实现范围内。

### 需真机

- 在 macOS 先执行 `xcodegen generate` 与完整 iOS 模拟器测试，再在 iPhone 12 验证 UVDoc 开关开启/关闭、模型缺失、Metal 失败回退、真实弯曲页质量与耗时。
- 验证相机拍摄忙碌态、中断恢复、重拍取消、删除确认、页面拖放/按钮排序。
- 用 VoiceOver 完成四角调整和页面排序，用特大辅助字体检查详情/裁剪布局，并检查浅色/深色模式对比度。
- 连拍 20 页及导出 20 页 PDF，使用 Instruments 记录峰值内存、耗时和页面顺序；阴影/低光/复杂背景照片检查找边、文字保真与黑白效果。
