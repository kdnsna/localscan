# LocalScan 开发计划

> 所有耗时、精度数字除非注明，都是 **目标值**，要在真机上实测后更新。基准机型：iPhone 12（A14，iOS 17）。

## 硬规则（任何 PR 都不得违反）
1. **不上云。** 不上传图片，不调用任何远程推理/OCR/转换服务，不在运行时下载模型或语言包。需要联网的改动必须先有新 ADR 并经用户同意。
2. **不含夸克的任何专有内容。** 不得包含夸克扫描王（或其他商业 App）的代码、模型、权重、脚本、图片、图标、文案素材；不得用夸克的输出当训练数据。夸克只能作为评测里的对照组。
3. **许可白名单。** 随 App 发布的模型、代码、数据集只能是 **MIT / Apache-2.0 / BSD**（2/3 条款）。新增依赖必须在 PR 里写明许可证和来源。
   - 可用于发布：UVDoc（MIT）、UVDoc-Dataset（MIT）、Doc3D（MIT）、GCDRNet（MIT）、DocShadow-SD7K（MIT）、DocRes（MIT）、DewarpNet（MIT）。
   - **只能当离线对照基线，永不随 App 发布、不进训练集**：DocTr、DocTr++、DocGeoNet、DocScanner（非商用许可）。
   - DocUNet Benchmark 没写许可证：只做内部评测，不分发。
4. **不提交用户照片。** 真实照片、测试集、扫描结果一律不进仓库（`.gitignore` 已拦截常见图片格式和 `testdata/`）。测试集放在仓库外，仓库里只存标注格式说明、评测脚本和汇总分数。
5. **保真模式不改字。** 「原图/保真」模式只做几何变换（裁剪、透视、展平），不做任何像素级的内容生成或修补。
6. **包体预算。** 随包模型合计 ≤ 25 MB。

## 里程碑

### M0：脚手架 + CI
内容：XcodeGen 工程（`project.yml`）、SwiftUI 占位 App、单元测试 target、GitHub Actions（macos-latest，iOS 模拟器构建 + 单元测试）、文档。

验收：
- [x] `xcodegen generate && xcodebuild test` 在 CI 上通过（main 分支绿色）。
- [x] README、PLAN、ADR-0001、CONTRIBUTING、调研资料已入库。

### M1：MVP——拍摄、自动找边、透视拉正、导出
内容：
- AVFoundation 自定义相机；预览帧跑 `VNDetectDocumentSegmentationRequest`，四边形叠加并做时域平滑（旧框向新框 smoothstep 过渡）。
- 自动拍摄：连续 N 帧（从 N=3–5 起调）角点位移 < 1–2% 对角线、倾斜 < 18° 时触发；也可手动按快门。
- 找边失败时给出内缩 6% 的默认四边形，进入手动裁剪编辑（可拖四角，带放大镜）。
- 拍后：保留原图（HEIC），另生成长边 1600–2048 px 的工作图；在工作图上做角点细化（沿边缘的梯度/亚像素拟合），映射回原图后用 `CIPerspectiveCorrection` 全分辨率拉正。
- 后台处理队列：拍下一页时上一页在后台处理，不阻塞相机。
- 多页管理（排序、删除、重拍、重新裁剪）。
- 导出：图片（JPEG/HEIC，JPEG 质量 0.80–0.88，默认 0.85）；多页 PDF（PDFKit / `UIGraphicsPDFRenderer` 写入 JPEG 数据，页面 200–300 DPI 等效）；通过系统分享面板或「文件」保存。

验收：
- [ ] 平整文档子集上，找边 IoU 中位数 ≥ 0.95，失败率（IoU < 0.90）≤ 5%，且 **不低于** VisionKit 系统扫描器和 Kimi 网页原型（经典基线）。（待真机；需用户照片）
- [ ] iPhone 12 上平纸单页「按快门 → 成品」P50 ≤ 1 s、P95 ≤ 1.5 s（目标）；连拍 10 页期间相机预览不掉到 30 fps 以下。（待真机）
- [ ] 冷启动到相机可用 ≤ 1.5 s（目标）。（待真机）
- [ ] 20 页 PDF 导出 ≤ 5 s，单页平均 ≤ 400 KB（A4、0.85 质量，目标）。（待真机）
- [ ] 飞行模式下全部功能可用；网络监控（Instruments / App 隐私报告）显示 0 个网络请求（静态部分已由 CI 无网络检查覆盖；真机 App 隐私报告待测）。（待真机）
- [x] 核心算法（尺寸计算、角点映射、平滑、稳定判定、PDF 组装）有单元测试。

### M2：弯曲书页展平 + 经典增强 + 保真模式
内容：
- **已落地（首个 M2 PR）**：经典「增强」——低分辨率背景/光照估计 → 除法归一化 → 温和对比度 + 轻锐化（Core Image，确定性）；不含模型、弯曲判定或展平。
- 弯曲判定：分割边缘偏离直线的程度 / 文本行曲率，给出「平纸 / 书页」路由。
- 书页展平：自训 MobileNet 级 6 点回归网络（四角 + 两条弯边中点，输入 256–320 px，≤ 2 MB，FP16/INT8 Core ML）→ TPS 网格 → Metal 全分辨率重采样。训练数据：UVDoc-Dataset、Doc3D，加自己用 Blender 合成的书页（不用任何非商用数据）。
- 残余弯曲严重时才升级到 UVDoc（Core ML FP16，约 15 MB，输入 488×712，只输出 45×31 网格，重采样放在模型外）。低档机（A14）可跳过 UVDoc。
- 外观模式：**原图/保真**（只做几何）、**增强**（低分辨率估计背景/光照 → 除法归一化 → 对比度曲线 + 轻锐化，Core Image/Metal，确定性）、**黑白**（在增强结果上自适应阈值）、**灰度**。
- 可选的 **AI 增强** 开关（本地，例如 GCDRNet 类光照估计网络在 256–512 px 上运行后上采样应用，≤ 5 MB），默认关闭，可与原图并排对比。

验收：
- [ ] 弯曲书页子集上，MS-SSIM 和 LD 都 **明显优于** 只做透视（目标：LD 降低 ≥ 30%），并报告与 UVDoc 单独使用的对比。
- [ ] DocUNet Benchmark 上报告 MS-SSIM / LD / AD（内部对照，含 DocTr 等非商用基线的离线分数）。
- [ ] 文字保真：保真模式、增强模式、AI 增强的 CER **都不高于** 同一张图「仅透视」结果的 CER（允许 +0.2 个百分点以内的噪声）。
- [ ] 增强模式确定性：同一输入两次输出逐像素一致（单元测试）。
- [ ] iPhone 12 上书页单页「按快门 → 成品」P50 ≤ 2 s（目标）；平纸路径不因 M2 变慢。
- [ ] 随包模型合计 ≤ 25 MB；每个模型的许可证和来源写进 `docs/MODELS.md`。

### M3：打磨——去手指、双页书本模式、速度调优、可选 OCR 文字层
内容：
- 去手指：`VNDetectHumanHandPoseRequest` / 前景分割找出页边手指 → 用页面背景色填充；压住文字时 **不编造文字**（只填背景，或保留原样并提示）。
- 双页书本模式：找书脊、拆成两页，逐页展平。
- 自动选择彩色/黑白；低光、抖动、倾斜提示；iOS 26 上可用 `DetectLensSmudgeRequest` 提示擦镜头（有就用）。
- 速度：模型空闲预热、量化、并行、按芯片三档降级（A14 及以下 / A15–A16 / A17 及以上）。
- 可选 OCR 文字层：Vision `VNRecognizeTextRequest`（中英文、`.accurate`）后台运行，在 PDF 里写入透明可搜索文字；不阻塞导出。

验收：
- [ ] 手指压边子集上，手指残留面积中位数 ≤ 1% 页面面积，CER 不劣于未处理。
- [ ] 双页子集上书脊定位误差 ≤ 2% 页宽，拆页后每页满足 M2 展平指标。
- [ ] 达到下文「客观评测」中全部目标值；P95 延迟相对 M2 降低 ≥ 20%。
- [ ] 带 OCR 层的 PDF 能在「文件」/预览 App 里搜索到文字；OCR 层 CER 在测试集上报告（中文印刷体目标 ≤ 3%）。
- [ ] 峰值内存（连拍 20 页）≤ 400 MB（目标）。

## 客观评测

### 测试集
- **至少 200 张真实照片**，由用户拍摄，存在仓库外（隐私文件先打码）。分类覆盖：平整 A4、弯曲书页（单页/双页）、褶皱纸、小票、证件、彩色页、阴影（手影/台灯）、手指压边、低光、复杂背景（木纹桌面）、斜拍 30°/45°。
- 每张标注：四个角点真值；书页类配一张 **平板扫描仪扫出的参考图**（ground truth）；以及人工校对过的真值文字。
- 拍摄设备：至少 iPhone 12，外加一台较新机型。
- 仓库里只放：标注格式说明（`eval/README.md`）、评测脚本、各版本的汇总分数表。

### 指标
| 维度 | 指标 | 目标（暂定） |
|---|---|---|
| 找边 | 四边形 IoU、角点误差（按对角线归一化）、失败率 | IoU 中位数 ≥ 0.95；失败率 ≤ 5% |
| 展平 | MS-SSIM、LD（局部形变）、AD；按 DocUNet 标准评测代码，和平板扫描参考图对比 | 书页 LD 比仅透视降低 ≥ 30% |
| 文字保真（最关键） | 对输出做 OCR，与真值文字算 CER / 编辑距离 | 任何模式的 CER 不高于「仅透视」 |
| 增强 | PSNR / SSIM（对比平板扫描参考图）、残留阴影面积；随机顺序人工盲评 | 盲评不输于夸克离线模式 |
| 速度 | 冷启动到相机就绪；按快门到成品 P50/P95；连拍 10 页总时长；20 页 PDF 导出；峰值内存；包体增量 | iPhone 12：平纸单页 ≤ 1 s，书页单页 ≤ 2 s（**目标值**） |

速度用 `os_signpost` 打点、Instruments 测量，冷/热启动分开，每项重复 ≥ 10 次取中位数。

### 对照组
- VisionKit 系统扫描器（免费基线）。
- **经典基线：Kimi 网页原型**（`prototypes/kimi-web/`，OpenCV.js Canny 找边 + 透视 + 经典增强）。
- 夸克扫描王（联网 / 离线各一轮）、扫描全能王、Genius Scan：只作为对照组统计分数，**不用它们的输出做训练**。
- 非商用模型（DocTr / DocTr++ / DocGeoNet / DocScanner）：只在评测机上离线跑分做参照。

同一批照片通过相册导入各 App 处理（排除拍摄手法差异），再加一轮实拍对比。

## Kimi 网页原型的参考价值
用户用 Kimi 做过一个网页原型（React + Vite + OpenCV.js + Tesseract.js + jsPDF），收录在 `prototypes/kimi-web/`。它有 Canny 轮廓找四边形、手动裁剪编辑、透视拉正、增强（灰度世界白平衡 + 直方图拉伸 + 反锐化）、自适应阈值黑白、灰度、Tesseract OCR、jsPDF A4 导出；没有曲面展平，也没有机器学习。

1. **UX 参考。** 它的页面流程（首页 → 相机 → 裁剪编辑 → 滤镜工作区 → 导出）和滤镜组（原图 / 增强 / 黑白 / 灰度）是原生 App 的交互参照。
2. **评测里的「经典基线」。** 它的经典 CV 流程作为评测对照组：原生 App 的 Vision / Core Image 路径必须在 **找边 IoU** 和 **耗时** 上都胜过它。
3. **原生 App 不复用它的代码。** 浏览器 + OpenCV.js（WASM）这条路比 Vision / Core Image 慢、也不如它们准；而且 Tesseract.js 在运行时从网络下载语言包，违反「不上云」硬规则，原生 App 改用 Vision OCR。
4. **值得移植的点子。** 找边失败时给一个 **内缩 6% 的默认四边形**；找边前把图 **缩到 1080 px** 再检测（原生上对应：在缩小的工作图上找边/细化角点，再映射回原图）。
