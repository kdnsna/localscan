# iPhone 扫描 App 调研报告：对标夸克扫描王的「扫描 + AI 矫正」

> 调研日期：2026-10-20（北京时间）｜范围：拍照扫描 → 自动找边裁剪 → AI 矫正（透视/曲面展平/去阴影/去手指/增强）→ 导出图片或多页 PDF。OCR 不是必需项。
> 说明：文中标【估计】的数字是我的推断，没有公开测量数据，需要实测。没标的数字都附了来源。

---

## 0. 一页结论（给不看技术细节的读者）

1. **夸克好用的地方是真的，但它主要靠云端。** 官方和媒体都说过它的流程是「手机上先裁剪 → 上传到云端用大模型处理 → 传回手机」。离线模式的模型是压缩了约 100 倍的版本，官方说效果保持在约 95%、处理约 2 秒（2022 年说法）。它的曲面展平是用**游戏物理引擎模拟书页弯曲**，生成大量训练数据训练出来的。
2. **夸克也有明显的槽点：** 有用户反映它连「原图」都会过一遍 AI，文字有「涂抹感」，甚至笔画变形成「甲骨文」；默认保存到云端；没网时用起来受限；订阅自动续费的投诉很多。**我们复刻的时候，可以把这几点直接做成卖点：** 全部在手机上处理、AI 只在需要时才开、保留一个「保真模式」。
3. **在 iPhone 上，大部分能力都可以完全本地实现，速度也够快：**
   - 找边：Apple 自带的 `VNDetectDocumentSegmentationRequest`，在有神经引擎的 iPhone 上能实时运行，免费，不占安装包体积。
   - 透视拉正：Core Image 自带的 `CIPerspectiveCorrection`，几毫秒就能完成。
   - 曲面展平：开源模型 **UVDoc**（MIT 许可，可以商用）约 790 万参数、存储约 30 MB，转成 Core ML 后可以在神经引擎上跑。我估计每页要几十到一两百毫秒【估计】。
   - 去阴影/增强：开源 **GCDRNet**、**DocRes**（都是 MIT），以及 **DocShadow-SD7K**（MIT）。
   - 导出 PDF：用 Apple 的 PDFKit。顺手加 OCR 成本很低，系统自带的 Vision 文字识别就能做，可以给 PDF 加一层可搜索的隐藏文字。
4. **要避开的坑：** 名气最大的一批曲面矫正模型（DocTr、DocTr++、DocGeoNet、DocScanner，作者都是中科大的冯浩）**禁止商用**，除非拿到书面授权。它们只能用来做对照实验，不能直接放进产品里。
5. **建议分三步做：** ① MVP：拍照、找边、拉正、经典增强、导出 PDF；② 加 AI 矫正：曲面展平和去阴影，模型在本地跑；③ 打磨：去手指、双页书本模式、自动选择彩色/黑白、速度优化。每一步都用同一套真实照片测试集，客观衡量「准」和「快」。

### 1.2 从竞品里得到的产品启示

- **「准」有两层意思：**几何要准（边找得对、书页拉得平），内容也要准（**不能改字**）。夸克和扫描全能王被吐槽最多的恰恰是 AI 把笔画「脑补」坏了。所以我们评测时必须专门测「字有没有被改」（见第 4.3 节）。
- **「快」主要体现在三处：**打开就是相机、对准就自动拍、拍完不用等预览就能拍下一页。vFlat 和 Adobe 高速模式快，就是因为做到了这几点。
- **本地处理是差异化卖点：** Scanner Pro、Genius Scan 都把「不出手机」当作主要宣传点，而夸克默认上传云端，这正是用户抱怨的地方。

### 2.2 公开资料里**没有**的信息（需要黑盒观察，见第 5 节）

- 用的是什么模型结构（是预测网格/形变场的方法，还是 3D 形状重建），没有找到论文或技术博客。
- **没有检索到**夸克（阿里/优视/动悦）名下关于书页展平或去手指的专利。相关专利多数属于高校或其他公司。这只能说明没搜到，不代表一定没有。
- 现在的版本（10.x）哪些步骤在本地跑、哪些在云端跑，2022 年之后没有新的公开说法。

### 2.3 我的判断（推断，不是事实）

夸克的优势主要来自三方面：**数据**（物理引擎合成数据 + 大量真实试卷）、**云端大模型**（不受手机算力限制，可以多个模型串联），以及**针对场景的规则**（单据/文件/试卷用不同风格）。对我们来说：
- 几何矫正（曲面展平）方面，开源模型加我们自己合成的数据，可以接近它的水平【推断】。
- 去手写、去水印、「脑补」模糊字这类重度处理，需要很大的模型，在手机上很难做到同等效果，而且你的需求里也没有这些。
- 我们可以在「忠于原文」和「完全本地」上做得比它好。

## 3. iOS 上可用的技术方案

### 3.1 Apple 系统自带能力（免费、不占包体积、本地运行）

| 能力 | 作用 | 优点 | 缺点 | 来源 |
|---|---|---|---|---|
| `VNDocumentCameraViewController`（VisionKit） | 一个现成的完整扫描界面 | 几行代码就能用；找边/自动拍/多页都有 | **无法定制**：不能改界面、不能控制自动拍摄、不能改裁剪流程；**没有曲面矫正**；输出分辨率和画质参数不受我们控制（需实测） | https://stackoverflow.com/questions/60505835 |
| `VNDetectDocumentSegmentationRequest`（Vision，iOS 15+） | 机器学习找文档：返回一张低分辨率的「文档区域」概率图 + 四个角点 | 在有神经引擎的设备上**能对相机画面实时运行**；对折角、被遮挡的角、不规则形状比传统方法稳；系统扫描器本身也在用它 | 只找**一个**文档；在 CPU/GPU 上跑达不到实时；概率图分辨率低，需要我们自己细化边缘 | WWDC21「Extract document data using Vision」 https://developer.apple.com/videos/play/wwdc2021/10041/ |
| `VNDetectRectanglesRequest` | 传统算法找四边形 | 只在 CPU 上跑，CPU 不忙时也能实时；可以一次返回多个矩形 | 遇到角被遮挡或纸张折叠就不准，需要我们自己判断哪个矩形是文档 | 同上 |
| `CIPerspectiveCorrection`（Core Image） | 按四个角点做透视拉正 | GPU 运行，非常快 | 只能处理平整的纸，弯曲的纸不行 | 同上（WWDC 示例代码） |
| `VNRecognizeTextRequest`（iOS 13+），`RecognizeDocumentsRequest`（iOS 26+） | OCR；新接口还能识别段落、表格、列表 | 本地运行、免费、支持中文；**可以用来给 PDF 加可搜索的文字层** | 中文手写和复杂版面不如商业 OCR（需实测） | https://developer.apple.com/videos/play/wwdc2025/272/ |
| `DetectLensSmudgeRequest`（iOS 26+） | 检测镜头脏污的置信度 | 可以在拍摄前提示「请擦一下镜头」，降低模糊照片 | 只支持 iOS 26 | https://developer.apple.com/documentation/Vision/DetectLensSmudgeRequest |
| PDFKit | 把多张图片合成 PDF，并叠加隐藏文字层 | 系统自带 | 压缩参数要自己调（JPEG 质量/分辨率），否则文件会很大 | Apple 文档 |

| **DocScanner** | 2025（IJCV） | 渐进式迭代矫正，DocUNet 基准上达到最好水平之一 | ❌ 非商用（同一作者的许可证） | https://github.com/fh2019ustc/DocScanner | 同上 |

方法汇总列表：https://github.com/fh2019ustc/Awesome-Document-Image-Rectification

**训练数据：** Doc3D（GitHub 仓库许可证为 MIT，https://github.com/cvlab-stonybrook/doc3D-dataset ）、UVDoc 数据集（MIT）。评测基准用 DocUNet Benchmark（130 张，https://www3.cs.stonybrook.edu/~cvl/docunet.html ，官网没写许可证，只用于内部评测比较稳妥）。我们也可以学夸克，用 Blender 等物理/布料模拟**自己合成**数据。这一步是我们能自主掌握的竞争力。

### 3.3 去阴影 / 外观增强模型

| 模型 | 作用 | 许可证 | 链接 | 手机可行性 |
|---|---|---|---|---|
| **GCDRNet**（2023，IEEE TAI） | 两级网络：先估计光照/阴影图，用它做除法校正，再还原细节；附带真实数据集 RealDAE（600 对） | **MIT** ✅（GitHub API 显示） | https://github.com/ZZZHANG-jx/GCDRNet | 两个 ONNX 模型合计约 21 MB；第三方纯 C# 移植在浏览器里每张约 700 ms（https://sdcb.ai/simdgcdrnet/ ）。在 iPhone 神经引擎上应该会快不少【估计】；可以先在低分辨率上估计光照，再放大应用到全图 |
| **DocShadow-SD7K / FSENet**（2023，ICCV） | 高分辨率文档去阴影，附带 SD7K 数据集（7000+ 张，2K 分辨率） | **MIT** ✅（仓库已归档） | https://github.com/CXH-Research/DocShadow-SD7K | 有社区的 ONNX/TensorRT 移植；在手机上需要裁小或分块处理 |
| **BEDSR-Net**（2020，CVPR） | 先估计背景色，再去阴影 | 官方没开源；非官方实现中有一个 MIT 版本 | https://github.com/CV-Reimplementation/BEDSR-Net-Reimplementation | 较老，适合当对照基线 |
| **DocRes** | 见上表，也能去阴影 | MIT ✅ | 见上 | 见上 |
| **经典算法（不用 AI）** | 背景估计（大核模糊或形态学）→ 原图除以背景 → 自适应阈值或对比度曲线 | 无许可问题 | — | GPU 上几毫秒。白描的「忠于原文」走的就是这类路线，适合做我们的「保真模式」 |

**去手指（推断方案，没有现成的成熟开源方案）：** 用 Vision 的手部姿态检测（`VNDetectHumanHandPoseRequest`）或前景分割，找出页面边缘的手指区域，再用页面背景色填充。如果手指压住了文字，就用轻量的图像修补（inpainting）模型。图像修补的开源模型（例如 LaMa，Apache-2.0）可以商用，但在手机上跑偏重，需要评估。vFlat 和 Adobe 都有这个功能，说明可以做到，不过他们的实现方式没有公开。

### 3.4 速度预算（目标值与估计）

以 iPhone 13 为最低基准机型、iPhone 15/16 为主力机型：

| 步骤 | 方法 | 估计耗时 |
|---|---|---|
| 实时找边（预览） | `VNDetectDocumentSegmentationRequest` | Apple 称可以实时运行（≥ 预览帧率） |
| 拍摄 | AVFoundation 拍 12MP 照片 | 系统决定 |
| 透视拉正 | `CIPerspectiveCorrection` | 【估计】< 20 ms |
| 曲面展平（只在检测到弯曲时运行） | UVDoc Core ML + Metal 重采样 | 【估计】50–200 ms |
| 去阴影/增强 | 经典算法 或 GCDRNet（低分辨率估计光照） | 【估计】经典 < 30 ms；AI 100–400 ms |
| 编码 JPEG/HEIC + 写入 PDF | ImageIO / PDFKit | 【估计】50–150 ms/页 |
| **目标** | 拍下一页时，上一页在后台处理 | **单页从按快门到出成品 ≤ 1 秒；连拍时不阻塞** |

所有【估计】都要在第 4 节的测试中用真机测出来，替换成实测值。

## 4. 推荐架构与分阶段计划

### 4.1 架构（本地优先，不依赖云端）

```
相机预览 (AVFoundation)
  └─ 每帧 → Vision 文档分割 → 角点平滑/稳定性判断 → 自动拍摄
拍摄 12MP 原图（保留原图，可随时重新裁剪）
  └─ 后台处理队列（按页并行，不阻塞下一次拍摄）
       1) 角点细化（在原图分辨率上沿边缘做亚像素拟合）
       2) 判断页面是否弯曲（例如分割边缘是否接近直线、文本行是否弯）
       3a) 平整 → CIPerspectiveCorrection
       3b) 弯曲 → UVDoc（Core ML，神经引擎）→ Metal 网格重采样
       4) 增强：保真模式（经典算法）/ 智能模式（GCDRNet 类模型）/ 黑白 / 原图
       5)（可选）去手指
       6)（可选）Vision OCR → PDF 隐藏文字层
  └─ 导出：JPEG/HEIC/PNG 图片，或多页 PDF（PDFKit，可调压缩）
存储：只存在本地 / iCloud 文件夹（由用户选择），不使用我们自己的服务器
```

**关键设计原则（直接针对竞品的槽点）：**
- AI 只在需要时运行：平整的纸不过展平模型。
- 永远保留原图，用户可以一键退回「保真」结果。
- 不「脑补」文字：增强模型只调光照和对比度，不生成新笔画。用第 4.3 节的「文字保真率」指标卡住这一点。

### 4.2 分阶段计划（工期为粗估）

| 阶段 | 内容 | 交付标准 | 粗估工期 |
|---|---|---|---|
| **P0 准备** | 建测试集（见 4.3）；用系统自带的 VisionKit 扫描器、夸克、扫描全能王跑一遍测试集，得到基线分数 | 有基线表 | 1 周 |
| **P1 MVP** | 自定义相机 + 实时找边 + 自动拍摄 + 透视拉正 + 经典增强（原图/保真/黑白）+ 多页管理 + PDF/图片导出；可选 Vision OCR 文字层 | 平整文档的找边准确率不低于 VisionKit；单页 ≤ 1 秒 | 2–4 周 |
| **P2 AI 矫正** | UVDoc 转 Core ML（coremltools，FP16）；用合成数据和真实数据微调；弯曲检测；AI 去阴影（GCDRNet/自训轻量模型） | 弯曲书页的展平指标（MS-SSIM/LD）明显优于只做透视；文字保真率不下降 | 4–6 周 |
| **P3 打磨** | 去手指、双页书本模式（自动拆成两页）、自动选择彩色/黑白、镜头脏污提示、性能优化（量化、并行）、低端机适配 | 达到第 4.3 节的全部目标值 | 3–4 周 |

### 4.3 「准」和「快」怎么客观衡量

**测试集（自己拍，不用网上的图）：**
- 至少 200 张真实照片【建议值】，分类覆盖：平整 A4、弯曲书页（单页/双页）、褶皱纸、小票、证件、彩色页、阴影（手影/台灯）、手指压边、低光、复杂背景（木纹桌面）、斜拍 30°/45°。
- 每张标注四个角点（真值），书页类再配一张**平板扫描仪扫出来的真值图**，再配一份**真值文字**（可以人工校对一遍 OCR 结果）。
- 拍摄设备固定：至少 iPhone 13 和一台较新机型。

**指标：**

| 维度 | 指标 | 说明 |
|---|---|---|
| 找边 | **四边形 IoU**、**角点误差**（像素，按图像对角线归一化）、找边失败率 | IoU 越高越好，可以设一个及格线，例如 IoU ≥ 0.95 算成功【建议值】 |
| 展平 | **MS-SSIM**、**LD（Local Distortion，局部形变）**、**AD** | 按 DocUNet 基准的标准评测代码计算，与平板扫描真值对比；同时在 DocUNet 公共基准上跑一遍，方便和论文比较 |
| 文字保真（最关键） | 对输出图做 OCR，计算与真值文字的 **CER（字符错误率）/ ED（编辑距离）** | 同时用来发现「AI 把字改坏了」：保真模式和 AI 模式的 CER 不能比原图透视结果更差 |
| 增强 | PSNR / SSIM（与平板扫描真值对比）、残留阴影面积 | 再配合人工盲评：随机打乱顺序，比较我们、夸克、扫描全能王的输出 |
| 速度 | 打开到相机就绪的时间；按快门到出成品的时间（P50/P95）；连拍 10 页的总时长；20 页 PDF 的导出时间；峰值内存；安装包增量 | 用 Xcode Instruments 的 os_signpost 打点，冷启动和热启动分别测，每项重复 ≥ 10 次取中位数 |

对照组：VisionKit 系统扫描器（免费基线）、夸克扫描王、扫描全能王、Genius Scan，同一批照片从相册导入处理（导入可以排除拍摄手法差异），另外再做一轮实拍对比。

## 5. 交给逆向机器人的问题清单（只观察行为，不复制代码和模型）

### 5.1 法律边界（非法律意见）
- 中国《计算机软件保护条例》第十七条允许「为了学习和研究软件内含的设计思想和原理，通过安装、显示、传输或者存储软件等方式使用软件」。**但这只覆盖学习设计思想，不允许复制。** 夸克的用户协议很可能禁止反编译和逆向工程，需要先读条款。
- **允许做的：** 作为普通用户使用 App，录屏，计时，观察界面和流程，对比输入/输出图像；查看自己设备上的网络请求**元数据**（域名、请求次数、上传大小、时间）；阅读公开文档和公开 API 文档。
- **不要做的：** 提取或复制模型文件、权重、代码、图片/图标素材；破解加密或签名、绕过证书校验去解密私有接口；调用非公开接口；把夸克的输出当作训练数据（可能涉及侵权和违反用户协议）。
- 如果要用夸克的效果当「参照答案」，合规的做法是：把它作为一个**对照组**，统计它在我们测试集上的分数，而不是用它的输出来训练我们的模型。

### 5.2 具体问题

**A. 云端还是本地**
1. 联网状态下扫一页时，有没有上传图片？上传几次、多大（原图大小还是压缩后的大小）？是在按快门之后、预览出来之前，还是点「保存」时才上传？
2. 开飞行模式时，哪些功能能用、哪些不能用？「无痕/离线模式」下的效果和联网时差多少？处理耗时差多少（用秒表或录屏逐帧计时）？
3. 曲面展平、去阴影、去手指，这三项分别在离线时能不能用？
4. 安装包里有没有明显的本地推理框架迹象（例如通过公开的第三方库清单或应用大小变化判断）？**只记录有没有，不要提取。**

**B. 拍摄端行为**
5. 实时找边框的刷新频率大约多少？在什么条件下会自动拍摄（静止多久、框稳定程度）？
6. 拍照时有没有用连拍或多帧合成（例如快门声次数、拍摄耗时）？
7. 光线不足、抖动、镜头脏污时，分别给出什么提示？
8. 出来的图片分辨率是多少？和相机原图的分辨率比是多少？

**C. 矫正行为**
9. 平整的 A4 纸会不会也经过「AI 处理」（V2EX 用户说原图模式也有涂抹感）？可以用带细小文字/细线的测试卡验证。
10. 弯曲书页：展平后，书脊附近的文字行能拉到多直？用打印的网格纸弯曲后拍摄，测量输出里网格线的弯曲程度。
11. 只拍到局部、看不到页面边缘时，还能不能展平？
12. 双页书本模式怎么拆页，书脊位置识别得准不准？
13. 去手指：手指压在文字上时，那块会被怎么填补？会不会编造出文字？
14. 各种滤镜（原图/增强/黑白/省墨等）的输出差别；自动选择「单据风格」还是「文件风格」时，判断依据可能是什么？
15. 同一张图处理两次，结果是否完全一样？（如果结果有随机性，说明可能用了生成式模型。）

**D. 导出**
16. 导出的 PDF：每页的分辨率/DPI 是多少，图像压缩格式是什么，有没有 OCR 文字层，文件大小大约多少/页？
17. 导出过程是在本地生成，还是从云端下载生成好的文件？

**E. 速度基准**
18. 从冷启动到相机就绪；单页从按快门到出成品；连拍 10 页的总时长；20 页 PDF 导出。分别在联网和离线时、在 iPhone 13 和新机上测。

## 6. 未决问题（需要你拍板或后续确认）

1. **只自用，还是要上架 App Store 甚至收费？** 这决定能不能用 DocTr 系列这类「非商用」模型。只自用的话，个人学习属于非商用范围，选择会多一些；如果要上架，就只用 MIT/Apache 许可的模型。
2. **最低支持的 iPhone 型号和 iOS 版本？** 建议 iOS 17+、iPhone 12 及以上（都有神经引擎）。iOS 26 的新接口可以做成「有就用」。
3. **要不要把 OCR 写进 PDF？** 系统自带 OCR 成本很低，建议作为可选开关。
4. **要不要逆向？** 按第 5 节的边界，只做黑盒观察就够用。是否需要把这份清单交给逆向机器人执行，需要你确认。
5. **测试集谁来拍？** 测试集要用真实照片。如果涉及合同、证件这类隐私文档，需要准备样例文件或打码。
